# 音频目录

**音频是这个产品最贵的部分，也是最不能省的部分。**

## 现在这里面是什么：占位音频，不是成品

这个目录里现在有第一周的 mp3，是**用 TTS 生成的占位文件**，只为了两件事：

1. 让小程序里有声音，能验证「点播放 → 出声 → 走完流程」这条链路
2. 让你先听一遍内容大概是什么样

**上线前必须全部换成真人录音。** 原因在产品文档里写了：这个音频是给家长听的发音样本，家长会照着它学。机器音会让家长学到不自然的语调。

占位音频可以用 `npm run make-placeholder-audio` 重建。

## 为什么只有第一周

小程序**主包上限 2MB**。60 个音频一共 4.4MB，全放进去开发者工具会直接报代码包超限。

所以音频分成两处：

| 目录 | 内容 | 进不进小程序包 |
| --- | --- | --- |
| `assets/audio/` | 全部 60 个 | **不进**，用于上传 CDN |
| `miniprogram/content/audio/` | 装满 1MB 预算为止（当前覆盖 d001-d007，即第一周） | 进 |

预算定在 1MB 而不是贴着 2MB，是因为代码本身还会长，留出余量比多塞几个音频重要。

超出预算的那部分，在开发者工具里点播放会提示「还没有录音」——这是正常的降级，等接了 CDN 就都有了。

**发布前必须把包内音频全部移到 CDN**，否则主包一定会超。

**要录什么、文件叫什么名字，看 `docs/recording-script.md`** —— 那份清单从卡片自动生成，录音时照着念就行。

**录完之后放哪里、要花多少钱，看 `docs/audio-hosting.md`** —— 三种托管方案的对比和接入步骤都在那里。

## 先搞清楚谁录、录在哪

| | 谁做 | 做几次 | 放在哪 |
| --- | --- | --- | --- |
| 录音 | **你（开发者）** | 全部 60 个文件各一次 | 你电脑上的这个目录，或 CDN |
| 播放 | 家长 | 每天点一次 | 手机从服务器拉取，不存储 |

**家长不录任何东西。** 音频是产品内容，录一次所有用户共用，像教材的配套磁带。用户手机上不存音频文件。

## 实际怎么录一遍

1. 用手机自带「语音备忘录」或电脑上的 Audacity 录。**不要用微信语音消息**——它是压缩过的 amr/silk，音质不够，格式还要转。
2. 按 `docs/recording-script.md` 的顺序念，注意词与词之间留出停顿。
3. 导出成 mp3，按清单里的文件名命名，一个字母都不能错。
4. 放进这个目录，回微信开发者工具点「播放示范」验证。

试听阶段随便谁录都行。正式内容建议找一位发音标准的配音，因为这是给家长听的示范——**家长会照着你的音频学发音，录错了家长就跟着学错了。**

## 两个文件分别是什么

每张卡对应两个音频，作用完全不同，不要混淆：

| 文件 | 是什么 | 给谁听 | 做什么用 |
| --- | --- | --- | --- |
| `d001-model.mp3` | **示范朗读**，慢速、带停顿 | **家长** | 让家长听清楚这个词组怎么说：发音、节奏、语调 |
| `d001-song.mp3` | **短歌**，15-30 秒 | 家长学会后**和孩子一起唱** | 给家长一个可以反复唱的东西 |

两个都不是"放给孩子听的内容"。区别在于：示范是家长照着学的样本，短歌是家长和孩子互动的工具。

## 为什么要做儿歌

不是装饰，是这个年龄最有效的记忆通道：

- **两岁对旋律的敏感度远高于语义。** 孩子通常先哼出调子，过几周才吐出词。
- **唱比说容易重复。** 家长愿意把一首歌唱二十遍，但不会把一句话说二十遍——而重复正是这个阶段唯一的学习方式。
- **歌能离开手机。** 洗澡、坐车、换尿布的时候都能唱，这是产品唯一能脱离屏幕的形态。

### 旋律从哪来

不用原创。**用现成的儿歌旋律套词最省事**，比如《两只老虎》或 Twinkle Twinkle Little Star 的调子，把歌词换成当天的核心语块。家长本来就会哼这些调子，接受度更高。

歌词结构见 `docs/recording-script.md`，就是把核心语块重复三遍。录音时录一条人声加简单伴奏即可。

## 硬规则

不要用 TTS。2 岁靠韵律、语调、节奏习得语音，机器合成的韵律不自然，孩子从中学不到东西，产品就降级成了背景噪音。

必须真人录音：慢速、夸张、有节奏。同一个词录多个变体，不要一个词只录一遍。

## 命名约定

```
d001-model.mp3   今天的示范朗读（慢速，带停顿，留出孩子回应的空档）
d001-song.mp3    今天的短歌（可反复唱，最好 15-30 秒，旋律简单）
```

## 录制规格

### 技术规格

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 格式 | mp3 | 小程序只认 mp3、m4a、aac 等常见格式，mp3 最稳 |
| 声道 | 单声道 | 教学音频不需要立体声，单声道体积减半 |
| 采样率 | 44.1 kHz | |
| 码率 | 64 kbps | 人声足够。30 秒约 240KB，60 个文件约 14MB |
| 响度 | -16 LUFS 左右 | 别削顶，别忽大忽小 |
| 时长 | 示范 25-40 秒 / 儿歌 15-30 秒 | |

### 内容规格（示范朗读）

按 `docs/recording-script.md` 的三步结构念：

```
1. 目标词各两遍，词间停 1 秒
2. 核心语块两遍，中间停 2 秒
3. 三个活动句各一遍，句间停 1.5 秒
```

**停顿是内容的一部分，不是留白。** 它是给家长的信号，告诉他「这里该停下等孩子了」。家长最常见的错误就是不停地说，用音频把节奏示范出来，比在文字里写「要留出空档」有效得多。

语速比平常说话**慢三分之一**，语调比平常**夸张一些**。

### 内容规格（儿歌）

- 歌词就是核心语块重复三遍
- 旋律简单到听两遍就能哼
- 人声清楚，伴奏不要盖过歌词
- 示范朗读里**不要**加背景音乐

### 录制环境

安静的小房间，关掉空调和风扇。手机自带的录音软件够用，离嘴 15-20 厘米，斜着一点避免喷麦。**不要用微信语音消息**——它是压缩过的 amr/silk，音质不够，格式还要转。

## JSON 里怎么写

卡片里**只写文件名**：

```json
"audio": { "model": "d001-model.mp3", "song": "d001-song.mp3" }
```

不要写 `content/audio/d001-model.mp3` 这样的路径。前缀由 `miniprogram/config.js` 的 `audioBase` 决定，写路径的话接 CDN 时会拼成 `.../audio/content/audio/d001-model.mp3`。校验脚本会拦住这种写法。

## 放到哪里

小程序主包上限 2MB，音频**不能**长期放在小程序包内。生产环境请：

1. 把音频传到 CDN 或对象存储；
2. 修改 `miniprogram/config.js` 里的 `audioBase` 为 CDN 域名；
3. 把该域名加入小程序后台的「downloadFile 合法域名」。

试听阶段可以用本地文件，但要注意包体积。
