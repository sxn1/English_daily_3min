# 部署到微信

从当前代码到小程序上线。**耗时几乎全在类目和备案，不在开发。**

---

## 零、先读完这一节，否则会白干

### 类目是最大的风险点

微信官方《开放的服务类目》里，**个人主体**在教育服务下只有一个可选三级类目「教育信息展示」，原文说明：

> 仅适用于提供教育信息展示服务。
> 注：该类目不支持提供教育视频播放/直播、课程产品销售等服务，建议去除。

这个小程序会播放音频教学内容，个人主体走教育类目**大概率被判「类目不符」**（对应《微信小程序平台运营规范》5.7 类目不符行为）。

### 推荐的定位

把产品定位成**家长育儿打卡工具**，而不是在线教育产品：

- 不卖课、不做课程产品销售
- 不做直播、不提供视频课程
- 功能上就是「每日任务卡 + 打卡记录 + 词汇清单」

这样更贴合「工具」大类，也能避开《小程序备案操作指引》里明确列出的「校外培训」前置审批（该条要求提供教育部门允许开展校外培训的审批文件）。

### 但这事我无法替你确认

英语启蒙算学科类还是非学科类，各地口径不一致，类目最终由平台审核判定。**上线前请务必先在小程序后台按实际功能试选一次类目**，拿不准就在微信开放社区发帖问官方客服。这一步问清楚，比后面被拒三次省事得多。

如果个人主体确实走不通，就需要企业主体（营业执照）。

## 一、备案（法定前提）

所有小程序都必须完成 ICP 备案，**未备案不能发布**。

依据：微信官方《小程序备案操作指引》引《互联网信息服务管理办法》——「未取得许可或未履行备案手续的，不得从事互联网信息服务」。2023 年 9 月 4 日起新小程序开放备案入口。

需要准备：

| 材料 | 提供方式 |
| --- | --- |
| 主办单位证件（个人身份证明 / 营业执照） | 开发者准备 |
| 主体负责人证件 | 开发者准备 |
| 小程序负责人证件 | 开发者准备 |
| 前置审批 / 专项审批（如被判定为校外培训） | 开发者准备 |
| 小程序负责人核验现场拍摄照片 | 在平台操作时完成 |
| 互联网信息服务承诺书 | 在平台操作时阅读确认 |
| 小程序备案真实性核验单 | 平台提供 |

时限：各省通信管理局不同，官方口径约 1-20 个工作日。

**如果被判定为校外培训，这里要额外提交教育部门审批文件——这就是为什么类目要先确认。**

## 二、从零到上线的步骤

依据微信官方《小程序协同工作和发布》：预览 → 上传代码 → 提交审核 → 发布。

| # | 做什么 | 在哪做 | 耗时 |
| --- | --- | --- | --- |
| 1 | 注册小程序，确定主体类型 | 微信公众平台 | 1 天 |
| 2 | 选服务类目 | 小程序管理后台 | 几分钟（但决定后面一切） |
| 3 | 提交备案 | 后台「小程序备案」 | 1-20 工作日 |
| 4 | 换真实 AppID | 改 `project.config.json` | 1 分钟 |
| 5 | 预览、自测 | 微信开发者工具 | — |
| 6 | 上传代码（填版本号 + 备注） | 开发者工具「上传」 | 1 分钟 |
| 7 | 提交审核 | 后台 → 版本管理 → 开发版本 | 1-7 天 |
| 8 | 发布（全量或分阶段） | 后台 → 版本管理 → 审核版本 | 即时 |

真实预期：**2-4 周**。

审核提交前请充分自测。官方明确提示「过多的审核不通过，可能会影响后续的时间」。

## 三、本项目需要改的地方（只有三处）

### 1. AppID

`project.config.json`：

```json
"appid": "touristappid"
```

换成后台的真实 AppID。`touristappid` 是测试号，只能本地开发。

### 2. `miniprogram/config.js`

```js
audioBase: '',            // 填 CDN 域名，例如 'https://cdn.example.com/audio'
subscribeTemplateId: ''   // 填订阅消息模板 ID
```

**音频必须走云存储或 CDN。** 小程序主包上限 2MB，音频放包内会直接超限。

如果你用微信云开发云存储，**这一步可以直接跳过**——`InnerAudioContext.src` 从基础库 2.2.3 起支持云文件 ID，不需要配域名也不需要备案。三种方案的完整对比见 `docs/audio-hosting.md`。

如果用自建 CDN，填完 `audioBase` 还要在后台把它加进「downloadFile 合法域名」，并且域名需要 ICP 备案。

**订阅消息模板请在小程序后台申请**，模板可选项与你的服务类目绑定。所以类目没定下来之前，每日提醒这个功能接不通。

### 3. 内容

7 张卡对应的 14 个音频文件还没录，见 `miniprogram/content/audio/README.md`。没有音频小程序也能跑（播放按钮会提示录音未补），但上线前必须补齐，否则核心体验是空的。

## 四、不用等审核的捷径：体验版

上传代码后，在后台把该版本设为**体验版**，生成体验二维码发给家长，扫码即可使用。

体验版不需要等备案和审核走完，这是**最近就能拿到真实反馈的路径**。

这一点和验证计划直接相关：在产品过审之前，你就能拿到那 10 个家庭的每日留存数据。如果核心假设被证伪，你省下的是整个备案和审核流程。

---

## 五、合规现状（当前版本的有利条件）

当前代码：

- 没有任何网络请求
- 没有账号体系、没有登录
- 没有调用录音、摄像头、位置、用户信息等隐私接口
- 进度只存在家长手机本地（`wx.setStorageSync`）

因此：

- 后台《用户隐私保护指引》可按「不收集用户信息」填写，不需要配置 `requiredPrivateInfos`（具体以后台实际要求为准）
- 不涉及儿童个人信息的收集与存储，合规负担极小

代价是换手机会丢进度，以后需要自己加导出功能。

**这是刻意换来的优势，不要为了埋点数据随手加一个第三方统计 SDK 把它毁掉。**

补充：如果以后要加语音互动、摄像头识物（产品文档里提过这个方向），就必须重新申报隐私指引，并向家长明示录音如何处理——最好本地处理、不上传。

## 六、提交审核时的注意点

审核时最容易出问题的地方：

1. **类目与功能不符**。审核员如果认为你在做在线教育，会直接判类目不符。
2. **审核员看不懂产品定位**。在「功能说明」里把它讲清楚：这是给家长的育儿打卡工具，孩子不直接使用屏幕，核心功能是家长拿到今日活动建议并记录孩子的语言表现。审核员不理解「家长工具」这个概念时最容易拒。
3. **音频无法播放**。审核时会实际体验，CDN 域名没配好或音频没上传会直接卡在功能不可用。

## 八、如果想先验证再决定要不要上线

阶段 0 的验证不需要任何部署：

1. 用微信群 + 在线文档，手动给 10 个家庭发每日任务卡（一张图 + 一段语音 + 一句家长引导）。
2. 观察第二天有多少人回来领。

如果 10 个家庭里只有 1-2 个能坚持一周，先改内容或节奏，此时你还没花任何注册、备案和开发的成本。

反向也成立：如果留存不错，你已经拿到了内容脚本，直接搬进小程序。
