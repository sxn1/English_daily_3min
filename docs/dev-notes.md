# 技术注意事项与踩坑记录

这份文档记录开发过程中确认过的问题，每条都注明依据。**不是可选阅读**——里面有几条是踩了才会发现、而且很难排查的坑。

## 一、已经修掉的坑

### 1. 静音状态下音频不出声

**问题**：`innerAudioContext.obeyMuteSwitch = false` 这种直接赋值的写法，在大部分手机上等于没设。

**依据**：微信官方 InnerAudioContext 文档，`obeyMuteSwitch` 属性说明写着「从 2.3.0 版本开始此参数不生效，使用 `wx.setInnerAudioOption` 接口统一设置」。

**后果**：家长手机常年静音。对这个产品来说，不响就等于坏了，家长会以为小程序有问题然后卸载。

**修复**：`player.js` 改成调用 `wx.setInnerAudioOption({ obeyMuteSwitch: false })`。

### 2. 音频路径写在卡片里，接 CDN 时会拼错

**问题**：原来卡片写的是 `content/audio/d001-model.mp3`（带路径），而 `config.js` 的示例是 `https://cdn.example.com/audio`。两者拼起来会变成 `.../audio/content/audio/d001-model.mp3`，多了一层。

**后果**：只在接 CDN 时才暴露，而且一眼看不出来。

**修复**：卡片里只写文件名（`d001-model.mp3`），路径前缀完全交给 `config.js` 的 `audioBase` 决定。校验脚本现在会拦住带路径的写法。

### 3. 倒计时切后台会跑偏

**问题**：原来每秒减一。小程序切到后台时 `setInterval` 会被节流甚至暂停。

**后果**：家长切回来会发现「3 分钟」实际过了五六分钟，产品承诺的时间不准。

**修复**：改成记录结束时间戳，每次用 `Date.now()` 反算剩余时间，切后台再回来会自动对齐。

### 4. `require('xxx.json')` 在小程序里根本不支持（真机才拦得住）

**问题**：卡片原本用 `require('./d001.json')` 加载。

**报错原文**：

```
module 'content/cards/d001.json.js' is not defined, require args is './d001.json'
```

看模块名里的 `.json.js` 就明白了：**小程序打包器把 require 的参数一律按 `.js` 解析**，于是去找 `d001.json.js`，找不到就判定模块未定义。

**这是整个项目里唯一一处静态检查查不出来、只有真机才能发现的错误。**

**修复**：JSON 只作为编辑时的源文件，另外生成一个内联的 JS 模块。新增 `tools/build-cards.mjs`，把 30 张卡渲染进 `miniprogram/content/cards/index.js`。`npm run validate` 会检查两者是否同步——改了 JSON 忘记重新生成，小程序加载的就是旧数据，而且**不会报错**，比直接报错更危险。

## 二、API 注意事项

| 事项 | 说明 | 依据 |
| --- | --- | --- |
| `innerAudioContext.src` 支持云文件 ID | 基础库 2.2.3 起。`player.js` 已透传 `cloud://` | 官方 InnerAudioContext 文档 |
| `obeyMuteSwitch` 必须用 `wx.setInnerAudioOption` | 基础库 2.3.0 起直接赋值不生效 | 同上 |
| `wx.vibrateShort` 的 `type` 参数 | 低版本基础库可能不支持，代码里已加 `fail` 兜底静默失败，不影响流程 | 防御性写法 |
| 小程序不能按变量路径动态 `require` | 卡片清单必须在 `content/cards/index.js` 里显式列出 | 小程序打包机制 |
| `subPackages` 外的目录会被打进主包 | 音频要放分包时，必须真的声明分包结构 | 官方分包文档 |

## 三、已知限制（暂时无解，是取舍）

- **主包 2MB 上限**：音频不能长期放在包内，必须走云存储或 CDN。
- **进度只存本机**：没有账号也没有服务器，换手机就丢。这是为了把合规负担降到零刻意做的取舍，见 `product-design.md`。
- **内容 7 天一轮循环**：目前只有 7 张卡，第 8 天开始重复。内容量是下一步要补的。

## 四、还没有验证过的东西

**这一节必须诚实对待：以下都没有在真机上跑过。**

| 项目 | 状态 |
| --- | --- |
| 所有 JS 语法 | 已验证（`node --check`） |
| 所有 JSON 可解析 | 已验证 |
| 卡片能正确加载 | 已验证（`npm run validate`） |
| 页面装配（事件绑定、跳转目标、标签配对） | 已验证（`npm run check`） |
| `require('xxx.json')` 是否可用 | **已确认为不支持**，已改为内联 JS 模块 |
| 卡片模块能否被加载 | 已验证（生成后可读出 30 张） |
| WXML 渲染 / WXSS 样式 | **未验证** |
| 页面跳转和参数传递 | **未验证** |
| 音频能否真的播放 | **未验证**（现在一个音频文件都没有） |
| 云开发 `cloud://` 播放 | **未验证** |

`require('xxx.json')` 已经在真机上报错并修复。WXML 标签由静态检查覆盖。剩下最大的未知是 WXSS 样式和音频播放。

### 为什么这些还没验证

官方微信开发者工具只提供 Windows 和 macOS 版本，开发环境是 Linux，跑不起来。

替代手段是 `npm run check`：静态检查页面装配——事件绑定的函数在 JS 里是否存在、跳转目标是否在 app.json 登记、WXML 标签是否配对。这三类是「编译能过但一跑就白屏」的典型原因。这个检查器本身做过反向验证：人为制造这三类错误，都能被抓出来。

但它**查不到**样式是否正确、渲染是否符合预期、音频能否播放。这些必须用开发者工具。

## 五、改动代码时请保持

- 不要引入任何第三方统计 SDK。当前版本没有任何网络请求、没有账号、没有隐私接口调用，这是合规上的核心优势。
- 不要给音频加自动连播。
- 不要在界面上给孩子加任何需要操作的东西。
